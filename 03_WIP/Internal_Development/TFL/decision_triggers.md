# Historical Context

As development complexity increased, a need emerged for more consistent evaluation criteria.

This file documents the criteria used when deciding whether a candidate observation, variable, anomaly, or mechanism should:

- receive additional testing,
- be promoted for formal consideration,
- remain unresolved,
- or be rejected.

Purpose:

The goal was to reduce arbitrary decision making by documenting explicit developmental criteria.

Relationship To Released TFL:

The contents of this file describe development methodology rather than framework theory.

The decision rules documented here are not themselves components of TFL.

## Promotion criteria

- Promote to framework when an effect is observed consistently across multiple conditions.
- Promote to framework when a variable is required to explain anomalies.
- Promote to framework when a mechanism outperforms existing explanation in test conditions.
- Promote to framework when behavior cannot be explained by baseline assumptions.

## Rejection & flagging criteria

- Reject observation when it fails to reproduce under controlled manipulation.
- Flag for further testing when evidence is inconsistent or context-dependent.

## Classification criteria

- Mark as candidate parameter when phenomenon appears continuous and measurable.
- Mark as structural element when phenomenon appears categorical or rule-based.
